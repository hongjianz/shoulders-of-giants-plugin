# 对抗验证规范化模板

> 优化项 #2 — 每个核心主张强制从三个角度进行对抗检验

## 对抗验证流程

```
收集完成后的核心主张列表
         │
         ▼
  对每个主张 P:
         │
     ├── 角度 A: 技术局限性
     │     "P 在什么条件下会失效或退化？"
     │     搜索方式: P + limitations / challenges / failure
     │
     ├── 角度 B: 乐观偏差  
     │     "P 的宣称是否被独立第三方验证过？"
     │     搜索方式: P + criticism / skepticism / overhyped / overly optimistic
     │
     └── 角度 C: 替代解释
           "同样的现象是否有其他解释？"
           搜索方式: 反向结论 + evidence / study

         ▼
  对每个角度:
     ✅ 找到高质量反方证据 → 下调置信度 + 记录来源
     ⚪ 未找到明确反方证据 → 标注"未证伪"，保留原始置信度
     ❌ 搜索无结果 → 记录为信息缺口
```

## 结果记录格式

```
### 主张：[主张标题]

初始置信度: [高/中/低]

对抗验证:
  A. 技术局限性
     结果: [✅/⚪/❌]
     证据: [来源和核心发现]
     置信度调整: [上调/下调/不变]

  B. 乐观偏差
     结果: [✅/⚪/❌]
     证据: [来源和核心发现]  
     置信度调整: [上调/下调/不变]

  C. 替代解释
     结果: [✅/⚪/❌]
     证据: [来源和核心发现]
     置信度调整: [上调/下调/不变]

对抗验证后置信度: [高/中/低]
调整说明: [总结为什么做了这个调整]
```

## 搜索策略建议

| 角度 | 推荐数据源 | 关键词模式 |
|------|-----------|-----------|
| A.技术局限性 | PubMed, Consensus | `X limitation`, `X challenge`, `X failure`, `X barrier` |
| B.乐观偏差 | Web Search, Consensus | `X overhyped`, `X skepticism`, `X overly optimistic` |
| C.替代解释 | PubMed, Web Search | `X versus Y`, `alternative explanation for X`, `X debate` |

## 质量要求

- 每个主张至少需要 **1个可靠的对抗数据点**（同行评议论文或可验证的产业信息）
- 如果三轮搜索后仍无结果 → 标记为 "未证伪" 而非 "已验证"
- 对抗证据的质量评级与原始发现相同（分级标注）
