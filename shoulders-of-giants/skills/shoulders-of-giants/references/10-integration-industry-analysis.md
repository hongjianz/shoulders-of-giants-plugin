# Shoulders-of-Giants + Industry-Analysis 集成指南

> 两个插件的分工定位：**Shoulders-of-Giants 负责证据层**（采集、验证、评级），**Industry-Analysis 负责解读层**（产业逻辑、趋势预测、战略建议）。

---

## 集成设计哲学

两个插件的设计遵循**关注点分离**原则。证据采集与产业解读是两种不同的认知任务，混在一起会导致：

- 产业分析的主观判断污染证据评估的客观性
- 证据对产业逻辑的约束力不够明确
- 双方的方法论边界模糊，难以独立演进

因此集成原则是：

```
Shoulders-of-Giants（事实层）
    │ 产出：带水印的证据集合 + 置信度评估
    │ 交付物：结构化调研摘要
    ▼
Industry-Analysis（判断层）
    │ 输入：证据集合 + 待解答的产业问题
    │ 产出：产业解读 + 情景推演 + 战略建议
    │ 交付物：金字塔结构产业分析报告
```

## 标准集成工作流（推荐）

### 流程总览

```
阶段A: 问题定界（协作）
    │  SoG 负责：问题分类、子问题分解
    │  IA 负责：定义行业边界、逻辑树构建
    │
    ▼
阶段B: 多源证据采集（SoG主导）
    │  执行6阶段调研流程
    │  产出：带水印的证据集合
    │
    ▼
阶段C: 产业解读（IA主导）
    │  SoG产出 → IA产业的输入
    │  执行产业分析流程的解读部分
    │  产出：金字塔结构分析 → 情景推演
    │
    ▼
阶段D: 综合输出（协作）
    │  整合证据层与解读层
    │  标注"哪些结论来自证据"、"哪些是解读"
    │  产出：完整调研+分析报告
```

### 详细步骤

#### 阶段A：问题定界

| 步骤 | SoG操作 | IA操作 |
|------|---------|--------|
| 1.接收问题 | 接收调研问题 | 接收产业分析需求 |
| 2.类型判断 | 分类（学术/产业/技术/竞争） | 分类（制造/软件/生物医药/前沿/能源） |
| 3.问题分解 | 拆为子问题 + 确定语言通道 | 构建逻辑树 + 初始假设 |
| 4.角色分配 | 确定哪些子问题需证据层，哪些需解读层 | — |
| 5.汇总展示 | 展示"本调研将使用SoG采集证据，IA解读产业逻辑" | — |

**关键交互**：向用户说明双插件方案，确认分工：

```
## 本调研采用双插件模式

分析范围: [产业名称]
证据采集: shoulders-of-giants（多源采集+验证+评级）
产业解读: industry-analysis（产业链分析+场景推演+战略建议）

子问题分工:
  [子问题1] → SoG 证据采集
  [子问题2] → IA 产业解读
  [子问题3] → SoG + IA 联合（SoG采集，IA解读）

是否同意此分工？
```

#### 阶段B：多源证据采集（SoG）

完整执行 Shoulders-of-Giants 6 阶段流程，产出以下结果：

**核心产出**:
```
1. 带水印的证据集合（按子问题组织）
   - [子问题1]  🔒 发现A
   - [子问题1]  📄⭐ 发现B
   - [子问题2]  🏢 发现C
   - ...

2. 对抗验证结果
   - 发现A: 3角度通过，高置信
   - 发现B: 技术局限✅，置信度下调至中
   - ...

3. 信息缺口声明
   - [缺失数据类型]
   - [不可用的数据源]
```

**传递给IA的关键信息**:
```
证据摘要文件格式:
────────────────────────────────────────
## 证据传递

### 子问题1: [标题]
汇总: [2-3句证据综合]

关键发现:
  - [发现A] 🔒 | 高置信
    来源: [引用]
    对抗验证: ✅✅✅

  - [发现B] 📄⭐ | 中置信
    来源: [引用]
    对抗验证: ✅⚪⚪（技术局限下调）
    注意: [解读层需留意的局限性]

### 信息缺口
  - [不可用的数据源]
  - [未覆盖的维度]

### 数据源清单
  - [完整引用列表]
────────────────────────────────────────
```

#### 阶段C：产业解读（IA）

IA 使用 SoG 传入的证据作为分析的基础数据，执行以下步骤：

| IA步骤 | 证据层输入 | 解读层操作 |
|--------|-----------|-----------|
| 行业边界定义 | SoG的子问题分解 | 结合产业知识精确定界 |
| 四维评估 | SoG采集的技术文献/市场数据 | 评估技术成熟度、市场阶段、产业链完整性 |
| 超前指标识别 | SoG采集的最新进展/融资/管线数据 | 识别前沿信号 |
| 稀缺控制点分析 | SoG提供的产业链各环节数据 | 判断利润/价值集中点 |
| 情景推演 | SoG提供的多角度证据 | 构建2×2场景矩阵 |
| 战略建议 | — | 基于证据+解读输出判断 |

**IA对证据的使用规则**:

```
证据使用守则:
──────────────────────────────────

✅ 正确做法:
  使用 🔒 证据作为分析的支撑锚点
  使用 📄⭐ 证据作为推理的中等支撑
  在信息缺口处标注"此推断基于有限证据"
  对对抗验证中发现反证的发现降低推断权重

❌ 错误做法:
  无视对抗验证下调置信度的发现
  将 🏢/🔬 作为核心论据
  在信息缺口处做出确定性的推断而不标注
```

#### 阶段D：综合输出

最终报告应包含两层信息的清晰标注：

## 使用方式

### 方案A：手动切换（推荐——当前版本）

当两个插件都安装后，在单次对话中分两步操作：

```
第1步: 启动 SoG
  /shoulders-of-giants AI酶设计对分子POCT行业的影响
  → 执行6阶段流程 → 产出证据集合

第2步: 在相同对话中启动 IA
  /industry-analysis --full AI酶设计行业
  → SoG产出的证据已在前面的对话中 → IA基于此做产业解读
```

### 方案B：自动串联（未来版本）

当 Claude Code 支持插件间通信后，可实现：

```
/shoulders-of-giants --to industry-analysis AI酶设计行业
```

或在 SoG 完成证据采集后自动触发 IA 分析。

## Troubleshooting

| 问题 | 原因 | 解决 |
|------|------|------|
| IA不知道SoG产出了什么 | 两个插件独立执行 | 在切换到IA前，明确总结SoG的关键发现并告知用户转述给IA |
| 证据传递不完全 | 对话上下文太长后丢失 | 将SoG的证据摘要写入文件，在IA阶段重新加载 |
| IA对SoG标注的🔒证据打了折扣 | IA不知道水印系统的含义 | 在IA开始时说明水印系统——🔒证据应作为核心分析锚点 |
| 用户不知道用哪个插件 | 不熟悉分工 | 使用 `/shoulders-of-giants --help 集成` 查看简要说明 |
