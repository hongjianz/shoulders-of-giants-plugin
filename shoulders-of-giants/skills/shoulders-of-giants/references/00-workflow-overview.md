# 00: 流程总览

## 完整流程

```
用户提问
  │
  ▼
┌─ 阶段1: 问题分类 + 语言通道评估 ──────────────────┐
│  自动判断问题类型 → 检查是否需要多语言通道        │
│  展示结果 → 用户确认/修改                         │
└──────────────────────┬──────────────────────────┘
                       ▼
┌─ 阶段2: 检索计划生成 ─────────────────────────────┐
│  按问题类型匹配最优数据源组合                      │
│  PubMed MeSH 预检 → 展示计划 → 用户确认/调整      │
└──────────────────────┬──────────────────────────┘
                       ▼
┌─ 阶段3: 多源并行采集 ─────────────────────────────┐
│  PubMed + Consensus + bioRxiv + WebSearch         │
│  检测0结果 → 自动放宽 → 首次结果展示               │
└──────────────────────┬──────────────────────────┘
                       ▼
┌─ 阶段4: 证据分层 + 深挖推荐 ──────────────────────┐
│  按来源/交叉验证/水印分级                          │
│  推荐深挖方向 → 用户选择                           │
└──────────────────────┬──────────────────────────┘
                       ▼
┌─ 阶段5: 对抗验证 ─────────────────────────────────┐
│  每个主张3角度检验 (A/B/C)                         │
│  置信度调整 → 记录来源                             │
│  快速模式: 可跳过                                  │
└──────────────────────┬──────────────────────────┘
                       ▼
┌─ 阶段6: 综合报告 ─────────────────────────────────┐
│  执行摘要 + 核心发现(带水印) + 对抗结果            │
│  产业影响时间线 + 信息缺口声明 + 数据源列表        │
└──────────────────────────────────────────────────┘
```

## 各阶段的交互密度

| 阶段 | 交互 | 建议判断 |
|------|------|---------|
| 1 | 展示分类+确认/修改 | 必选——防止方向跑偏 |
| 2 | 展示计划+确认/调整 | 必选——确保检索策略准确 |
| 3 | 展示结果摘要 | 展示为主，不阻塞 |
| 4 | 展示发现+选择深挖方向 | 可选——用户可跳过深挖 |
| 5 | 展示对抗结果 | 展示为主，可深入争议点 |
| 6 | 输出报告 | 展示为主 |

## 快速模式 vs 标准模式 vs 深度模式

```
快速模式: 阶段1 → 2 → 3 → 4 → [跳过5] → 6 (2-3轮交互)
标准模式: 阶段1 → 2 → 3 → 4 → 5 → 6 (4-6轮交互)
深度模式: 标准 + 时间序列分析 + 引文追踪 (5-8轮交互)
```

## 与 industry-analysis 联动的推荐流程

1. `/shoulders-of-giants <topic>` → 得到带水印的可信度报告
2. 将报告中的核心发现作为 input
3. `/industry-analysis --quick <industry>` → 做产业解读/预测/卡点分析

这种分工利用了各插件的核心能力：shoulders-of-giants 擅长信息采集与验证，industry-analysis 擅长产业洞察与预测。
