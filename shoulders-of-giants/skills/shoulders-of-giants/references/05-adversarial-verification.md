# 05: 对抗验证

## 核心理念

对抗验证不是找茬，而是对结论的**压力测试**——通过主动寻找反方证据，
判断结论在多大程度上站得住脚，识别出那些"听起来合理但经不起推敲"的论断。

## 验证标准

每个核心主张（即最终报告中准备呈现的主要结论）都必须经过3角度检验：

```
对于主张 P:
  ┌─ 角度 A: 技术局限性
  │    问题: "P 在什么条件下会失效或退化？"
  │    搜索: P + limitations / challenges / failure / edge case
  │    预期: 找到使P不成立的边界条件
  │
  ├─ 角度 B: 乐观偏差
  │    问题: "P 的宣称是否被独立第三方验证过？"
  │    搜索: P + criticism / skepticism / overhyped / overly optimistic
  │    预期: 找到对P的过度宣称的批评或修正
  │
  └─ 角度 C: 替代解释
       问题: "同样的现象是否有其他解释？"
       搜索: 反向结论 + alternative explanation
       预期: 找到支持反方结论的证据
```

## 结果记录格式

```
### 主张：[主张标题]

初始置信度: [高/中/低/极低]

对抗验证:
  A. 技术局限性
     结果: [✅/⚪/❌]
     核心发现: [2-3句话摘要]
     来源: [引用链接]
     权重: [强/中/弱]
  
  B. 乐观偏差
     结果: [✅/⚪/❌]
     核心发现: [2-3句话摘要]
     来源: [引用链接]
     权重: [强/中/弱]
  
  C. 替代解释
     结果: [✅/⚪/❌]
     核心发现: [2-3句话摘要]
     来源: [引用链接]
     权重: [强/中/弱]

对抗验证后置信度: [高/中/低/极低]
调整说明: [为什么做了这个调整]
```

## 结果说明

| 标识 | 含义 | 对置信度的影响 |
|------|------|---------------|
| ✅ | 找到高质量反方证据 | 下调置信度 + 在报告中记录 |
| ⚪ | 未找到明确反方证据 | 标注"未证伪"，不调整 |
| ❌ | 搜索无结果/数据源不可用 | 记录为信息缺口 |

## 质量要求

- 每个角度至少执行1次搜索
- 反方证据的质量评级被纳入最终的证据水印系统
- "未找到反方证据"不等于"证明正确"——在报告中标注为"未证伪"
- 如果3个角度全部为⚪或❌，主张的置信度不受影响（但需标注信息缺口）
- 如果1个角度为✅，根据权重决定是否下调置信度
